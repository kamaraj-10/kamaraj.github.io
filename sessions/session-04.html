Session 4: Vector Databases & Embeddings

The Technology Behind Smart Retrieval

What are Embeddings?

Embeddings are a way to represent text, images, or other data as numbers that a computer can understand and compare. They capture the meaning and context of the information in a format that machines can work with.

Simple Analogy: Think of embeddings like a fingerprint for text. Each piece of text gets a unique numerical pattern that represents its meaning. Similar texts will have similar fingerprints.

How Embeddings Work

Embeddings convert words and sentences into lists of numbers. For example:

"The cat sat on the mat" might become:
[0.2, -0.5, 0.1, 0.8, -0.3, 0.6, 0.9, ...] (hundreds of numbers)

"A feline sat on the rug" might become:
[0.21, -0.48, 0.12, 0.79, -0.31, 0.61, 0.88, ...] (very similar numbers!)

Key Properties of Embeddings

  • Meaning Capture: Similar meanings produce similar embeddings
  • Dimensional: Usually 100s or 1000s of dimensions
  • Dense Representation: All dimensions contain meaningful information
  • Learnable: Can be improved through machine learning

Vector Databases

Vector databases are specialized databases designed to store and search embeddings efficiently. They're optimized for finding similar items quickly, which is perfect for RAG systems.

Why Vector Databases?

Traditional databases are designed to find exact matches. Vector databases are designed to find similar items. This is crucial for RAG because you need to find "similar enough" documents, not just exact matches.

Traditional Database:
"Find rows where age = 25" ✓ Works well
"Find rows similar to this person" ✗ Inefficient

Vector Database:
"Find vectors similar to this embedding" ✓ Very efficient

Popular Vector Databases

  • Pinecone: Cloud-based, managed service, easy to use
  • Weaviate: Open-source, self-hosted, feature-rich
  • Milvus: Open-source, scalable, high performance
  • Chroma: Lightweight, great for development
  • FAISS: Facebook's library for similarity search
  • Qdrant: Rust-based, very fast and efficient

The RAG Workflow with Embeddings

Here's how embeddings and vector databases work in a RAG system:

During Setup (Indexing)

  1. Take your documents (customer support FAQs, product manuals, etc.)
  2. Break them into chunks
  3. Convert each chunk into an embedding
  4. Store embeddings in a vector database
  5. System is now ready to serve queries

During Query (Retrieval)

  1. User asks a question
  2. Convert the question into an embedding
  3. Search the vector database for similar embeddings
  4. Return the most similar documents
  5. Pass these to the generator to create a response

Similarity Search Methods

Vector databases use various methods to find similar vectors:

Euclidean Distance

Measures the straight-line distance between two points in space. Similar to measuring distance on a map.

Cosine Similarity

Measures the angle between vectors. Great for comparing direction/meaning rather than magnitude.

Dot Product

Quick similarity measure, often used in production systems for speed.

Embedding Models

You need a model to create embeddings from text:

  • OpenAI Embeddings: High quality, paid API
  • Sentence Transformers: Open-source, free, good quality
  • BERT Embeddings: Popular, multilingual options
  • LLaMA Embeddings: Open-source option

Best Practices for Embeddings

  • Consistency: Use the same embedding model for indexing and retrieval
  • Chunking: Break documents into appropriate sizes (typically 256-512 tokens)
  • Metadata: Store document metadata alongside embeddings for filtering
  • Updating: Re-embed documents when content changes
  • Monitoring: Track retrieval quality metrics

Challenges and Considerations

  • Embedding Drift: Embeddings from different models may not be compatible
  • Storage: High-dimensional vectors take up significant space
  • Computational Cost: Embedding large documents is computationally expensive
  • Context Loss: Some information is lost when converting text to vectors

Key Takeaways

  • Embeddings convert text into numerical representations that capture meaning
  • Vector databases are optimized for similarity search, perfect for RAG
  • Similar texts produce similar embeddings
  • During indexing, documents are embedded and stored
  • During retrieval, questions are embedded and compared to stored embeddings
  • Consistency in embedding models is crucial
  • Vector databases enable fast, semantic retrieval
