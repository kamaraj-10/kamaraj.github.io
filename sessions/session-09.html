Session 9: Advanced RAG Techniques

Taking RAG to the Next Level

Moving Beyond Basic RAG

Once you have a working basic RAG system, there are many advanced techniques you can employ to significantly improve performance. This session covers techniques used in production systems.

1. Re-Ranking

Instead of using the top-k results from initial retrieval, you can use a specialized re-ranker model to re-score and re-rank results.

How It Works:

  1. Initial retrieval returns top-100 candidates (fast but less accurate)
  2. Re-ranker model scores each candidate more carefully
  3. Top-k by re-ranker score is passed to generator

Benefits:

  • Improved retrieval quality
  • Still maintains reasonable speed
  • No need to change indexing
Trade-off: Takes longer than basic retrieval but produces better results than basic retrieval alone.

2. Query Expansion and Reformulation

Instead of retrieving based on the original query alone, expand it with variations and related queries.

Techniques:

  • Synonym Expansion: Add synonyms automatically
  • Query Reformulation: Rephrase query in different ways
  • Sub-query Generation: Break complex query into sub-queries
Original Query: "laptop warranty"

Expanded Queries:
- "laptop warranty period"
- "computer warranty"
- "device coverage"
- "hardware protection"

3. Multi-Hop Retrieval

For complex questions requiring information from multiple documents, use multi-hop retrieval to retrieve in stages.

Process:

  1. Retrieve documents for first part of question
  2. From those results, identify what additional information is needed
  3. Retrieve documents for second part
  4. Combine all retrieved information
Question: "What are the benefits of the premium subscription offered in North America?"

Hop 1: Retrieve documents about premium subscription
Hop 2: Retrieve documents about North America specific offerings
Combine: Find intersection of both

4. Hybrid Search (Keyword + Semantic)

Combine keyword-based search with semantic search and intelligently merge results.

Why Hybrid is Better:

  • Keyword Search: Great for exact matches, fast
  • Semantic Search: Great for understanding meaning
  • Together: Best of both worlds

Merging Strategies:

  • Union: Combine all results, remove duplicates
  • Reciprocal Rank Fusion: Score based on rank in both systems
  • Weighted Average: Combine scores with weights

5. Metadata Filtering and Contextualization

Use metadata (dates, categories, sources) to filter or contextualize search results.

Use Cases:

  • Date-Based: "Recent articles" - filter by publication date
  • Category-Based: "Documentation only" - filter by source type
  • Version-Based: "Latest version" - filter by product version
  • Author-Based: "Official sources only" - filter by author
Query: "What are the privacy policies?"

With Filtering:
- Retrieve only from "official" category
- Only documents updated in last 6 months
- From your company sources only

6. Caching and LRU (Least Recently Used)

Cache results for frequently asked questions to reduce latency and compute costs.

Implementation:

  • Store responses for common queries
  • Return cached response if query matches
  • Update cache when documents change
  • Track usage patterns

Benefits:

  • Dramatically faster responses for common queries
  • Reduced API costs
  • Better user experience

7. Feedback Loop and Learning

Collect user feedback to identify failures and improve the system over time.

Types of Feedback:

  • Explicit: Users rate responses (thumbs up/down)
  • Implicit: Track query reformulations, session abandonment
  • Manual Review: Human review of failing cases

Using Feedback:

  • Identify problematic queries
  • Find gaps in knowledge base
  • Optimize prompt templates
  • Improve retrieval algorithms

8. Graph-Based Retrieval

Represent documents as nodes in a graph with relationships, enabling smarter traversal and retrieval.

Benefits:

  • Find related documents through relationships
  • Understand document hierarchy
  • Navigate complex knowledge structures

9. Contextual Compression

Instead of passing entire documents to the generator, compress them to only the relevant portions.

Why It's Important:

  • Reduces token usage (lower cost)
  • Reduces hallucinations (less irrelevant info)
  • Faster generation (shorter context)

10. Iterative Generation with Feedback

Generate an initial response, evaluate it, and regenerate if needed to improve quality.

Process:

  1. Generate initial response
  2. Check quality (factuality, completeness)
  3. If poor, retrieve additional information
  4. Regenerate with more context

Performance Optimization

Latency Optimization

  • Use approximate nearest neighbor search
  • Implement caching
  • Batch requests
  • Use GPU acceleration

Cost Optimization

  • Use smaller embedding models
  • Implement caching for common queries
  • Use open-source models instead of APIs
  • Compress retrieved documents

Monitoring and Observability

Track important metrics to understand system performance:

  • Retrieval quality metrics (precision, recall, MRR)
  • Generation quality (user ratings, accuracy)
  • System metrics (latency, cost, error rate)
  • Business metrics (user satisfaction, conversion)

Key Takeaways

  • Re-ranking improves retrieval quality significantly
  • Query expansion handles variations of questions
  • Multi-hop retrieval handles complex questions
  • Hybrid search combines best of keyword and semantic search
  • Metadata filtering enables precise control
  • Caching dramatically improves performance for common queries
  • Feedback loops enable continuous improvement
  • Monitoring is essential for production systems
