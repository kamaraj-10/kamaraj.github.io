Session 8: Building Your First RAG System

Hands-On Guide to Creating a Simple RAG

Overview: What We'll Build

In this session, we'll walk through the process of building a simple RAG system that can answer questions about a company's policies. This will be a practical, step-by-step guide.

Project Scope: A simple Q&A system that answers questions about a company's leave policy using their documentation.

Step 1: Prepare Your Documents

The first step is to gather and organize your documents. This will be your knowledge base.

What to Do:

  1. Collect all relevant documents (PDFs, text files, web pages)
  2. Organize them logically
  3. Ensure documents are high quality and up-to-date
  4. Remove duplicates
  5. Clean up formatting
Example Document Structure:
/documents/
  leave-policy.txt
  work-from-home-policy.txt
  vacation-guidelines.txt
  sick-leave-policy.txt

Step 2: Choose Your Tools

Select the right tools for your RAG system. Here are popular options for beginners:

Embedding Model

  • Sentence Transformers: Free, open-source, easy to use locally
  • OpenAI Embeddings: High quality, cloud-based, paid

Vector Database

  • Chroma: Simple, local-first, great for development
  • Pinecone: Cloud-based, managed, easy to scale

Language Model (Generator)

  • OpenAI GPT: Most popular, high quality, paid API
  • Open-source Models: Llama, Mistral, etc. (free but require hosting)
Beginner-Friendly Stack:
- Embeddings: Sentence Transformers
- Vector DB: Chroma
- Generator: OpenAI GPT-3.5

Step 3: Set Up Your Environment

Install necessary libraries and set up your development environment.

Python Packages to Install:
pip install langchain chroma-db sentence-transformers openai

Step 4: Create Embeddings (Indexing)

Convert your documents into embeddings and store them in your vector database.

Process:

  1. Load your documents
  2. Split them into chunks (256-512 tokens each)
  3. Create embeddings for each chunk
  4. Store in vector database
High-Level Process:

Document: "Employees get 20 days of annual leave..."
↓
Chunks: ["Employees get 20 days", "of annual leave", ...]
↓
Embeddings: [[0.2, -0.5, 0.1, ...], [0.21, -0.48, ...], ...]
↓
Stored in Vector DB

Step 5: Build the Retrieval System

Create a retriever that can find relevant documents based on a query.

Implementation Steps:

  1. Convert user query to embedding
  2. Search vector database for similar embeddings
  3. Retrieve top-k most similar documents (typically k=3-5)
  4. Return relevant documents

Step 6: Build the Generator Pipeline

Create the final RAG pipeline that retrieves documents and generates responses.

RAG Pipeline:

1. User asks: "How many days of leave do I get?"
2. Retrieve relevant documents about leave policy
3. Create prompt with retrieved documents
4. Send to language model
5. Get generated response
6. Return to user

Step 7: Test and Evaluate

Test your RAG system with real questions and measure its performance.

Test Cases:

  • Direct Questions: "What's the annual leave policy?" (should retrieve relevant docs)
  • Synonyms: "How many vacation days?" (should understand and retrieve)
  • Edge Cases: "Can I work from Mars?" (should gracefully handle)
  • Partial Information: Questions not fully covered in docs

Metrics to Track:

  • Relevance: Are retrieved documents actually relevant?
  • Accuracy: Are generated answers correct?
  • Speed: How fast is the response?
  • User Satisfaction: Would users accept this response?

Step 8: Iterate and Improve

Use evaluation results to improve your RAG system.

Improvement Strategies:

  • Better Chunking: Experiment with different chunk sizes
  • Better Prompts: Refine your system prompts
  • Better Documents: Update or reorganize your knowledge base
  • Better Retrieval: Try hybrid search or re-ranking
  • Feedback Loop: Learn from user corrections

Common Challenges and Solutions

Challenge: Poor Retrieval Quality

Solutions: Better document organization, hybrid search, query expansion

Challenge: Hallucinations

Solutions: Better prompts, explicitly instruct to stick to documents

Challenge: Slow Response Times

Solutions: Use smaller embedding models, add caching, optimize vector search

Challenge: Stale Information

Solutions: Regularly update documents, monitor for changes

Next Steps After Building

  • Deploy to a web service
  • Add user feedback mechanism
  • Monitor performance metrics
  • Scale to more documents
  • Integrate with other systems
  • Add analytics and logging

Key Takeaways

  • Building RAG starts with preparing quality documents
  • Choose appropriate tools for your use case
  • Indexing creates embeddings and stores them
  • Retrieval finds relevant documents for queries
  • Generation creates responses based on retrieved docs
  • Testing and iteration are crucial
  • Most failures come from poor retrieval or documents
  • Start simple and improve gradually
